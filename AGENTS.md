# Breach Command contributor instructions

These instructions apply to the entire repository. Preserve the game as a polished, public, single-player incident-response simulation. Changes should strengthen the player experience without turning the project into a reproduction of the commercial Backdoors & Breaches deck.

## Product boundaries

- Keep all scenarios, card wording, characters, art direction and rules text original.
- Retain the existing attribution and the statement that the project is unofficial and not endorsed by the original creators.
- Do not add official card text, commercial artwork, Consultants content or other proprietary deck material.
- Keep the game fictional and educational. It must not connect to, scan or modify real infrastructure.
- Preserve the rule-based computer Incident Captain. Do not introduce a required AI service, account, backend or network dependency.
- Keep campaign, session, preferences and telemetry data local to the player's browser.
- Reach local storage only through `lib/storage.ts`. Storage can be blocked or full, and the game must keep playing and say so rather than fault.
- Only an operation still in progress is offered for resume; a finished operation's save is cleared. A save written by a newer build is never deleted or overwritten — `sessionFromNewerBuild` tells it apart from a damaged one — because an older bundle served offline would otherwise destroy it. Before anything else is written to the slot it moves to `PARKED_SESSION_KEY`, and a build that can read a parked save moves it back and offers it for resume. Beginning a new operation while one is saved says that it replaces it, and with a save present the assignment screen's sticky primary button resumes it, with beginning anew a separate button beneath: on a laptop the saved card sat under a sticky "Begin investigation" that replaced the save without asking.
- A result is recorded once per operation, from whichever transition ended it: a decision, command event, sector decision, map action or correlation can lose an operation as surely as a procedure. The balance record counts an authorised exercise apart from a loss, as the campaign does.
- Sound, music and haptics never throw into the game. A failed `AudioContext` once left the turn lock held and every later action refused.
- A hook that both reads stored state on mount and writes it on change must not write before it has read. Every effect runs on mount, so an ungated write puts the defaults straight over the player's settings. `tests/e2e/persistence.spec.ts` covers this from the outside.

## Technical baseline

- Framework: Next.js 16 with React 19, built and hosted natively on Vercel.
- Language: TypeScript with strict checking.
- Package manager: pnpm. Preserve `pnpm-lock.yaml` and do not switch package managers.
- UI primitives: reuse the components in `components/ui` when a suitable primitive already exists.
- Icons: use `lucide-react` rather than custom icon SVGs.
- Hosting identity: the existing Vercel project `breach-command`. Preserve `vercel.json` and the checkout-local `.vercel/project.json` link; do not create a duplicate Vercel project.

## Repository map

The game screen and every dialog load on demand: each mounts the first time it opens and stays mounted so it closes with its own focus return, all are warmed when the browser is idle (which also puts them in the offline cache, since the service worker keeps every same-origin script it sees), and the game screen keeps a `main` landmark with a heading while its script arrives. Each is wrapped in `FaultBoundary` (`components/game/fault-boundary.tsx`), so a render fault stays in its own part, says the operation is saved, and offers a diagnostic to copy: build, browser and error, nothing personal and nothing sent.

A string two components share is written in each catalogue with the same words. `index.ts` translates with `Intl.PluralRules` and `Intl.NumberFormat`, generates the pseudo-locale `en-XA` (accented, a third longer), and shows a key whose catalogue has not loaded as the key itself. A table of labels at module scope holds keys typed `MessageKey` and is translated where it renders (`t(lossStatus[cause])`), never with `textFor()` at load, which would read the locale before hydration; a helper outside a component takes `t: Translate` as a parameter. A sentence with an element inside it is one message with markup, `<strong>{remaining}</strong> of {limit} turns remaining`, read with `rich(key, params, { strong: chunk => <strong>{chunk}</strong> })` so the element keeps its class (`lib/i18n/rich.ts`; tags do not nest). ## Game-engine invariants

- Treat game state as immutable. Clone collections before changing them and return a new `Game` object from transitions. A new collection on `Game` belongs in every transition's clone block, and `tests/game.test.ts` asserts this for `playTurn`.
- Every technique maps to its nearest MITRE ATT&CK Enterprise technique (`attackMitre` in `lib/game.ts`, asserted complete in `tests/content.test.ts`). The ID is shown in the review's attack chain and on the facilitator sheet, after the operation, never during play: the ID names the technique. The facilitator sheet prints the whole hidden chain and is reached from the review with the warning that it gives the answer away.
- A term that appears in play has a `plainLanguage` entry; `tests/glossary.test.ts` finds every acronym in the authored prose and checks a list of field terms against the glossary. Add the term to the test's list when content introduces new field vocabulary. "IT" stays out: read without case, it would gloss every "it".
- Print rules clear the dialog's `translate` in a rule of its own: the minifier folds `transform:none; translate:none` in one rule into a single transform and drops the translate, which printed the review half off the page.
- Keep hidden attack-chain information out of player-facing text until it has been revealed, and out of player-facing numbers. The planning bonus once applied only when the declared reading matched the hidden route: the Captain's Report said "including hypothesis bonus", a protected failure read "the route under test was the right one", and even with both words gone the report's total less the preview's modifier gave the answer. Nothing hidden now touches the roll. Every failed roll the grace did not absorb reads as `FAILED_CHECK`.
- A procedure consumes one turn. Procedure cooldown, difficulty thresholds, turn limits and end-state checks must remain internally consistent.
- Pending evidence decisions, command events and sector set pieces are blocking states. The player must resolve them before changing hypotheses, infrastructure focus or running another procedure.
- The response phase begins only after all four stages have been revealed. A completed response requires both containment and recovery choices.
- An authorised exercise is a conclusion the investigation earns. It requires at least two confirmed stages; an earlier draw clears part of the activity and play continues. It is not a defeat and must never be recorded as one in `recordCampaignResult`; its score leaves containment and recovery out and scales the other parts to 100, because "not scored" sat beside 0 of 20 inside the total; and it clears the case in the campaign as a win does: a player who confirmed the activity was a drill once found the case still open and nothing in the game said why.
- Crisis must stay mechanically distinct, not merely tighter: fewer map actions, a higher starting objective, a faster objective advance and an unprompted adversary re-route on the escalation beat. The re-route changes the stage after the one under test (`crisisRerouteTarget`), so the actor adapts ahead of the investigation. Re-routing the stage under test discarded everything the player had ruled out about it every two or three turns: sound reasoning was worth 1.9 points at Crisis, against 7.7 now, while a player who never revised lost nothing either way.
- Response is a three-stage sequence: containment, assurance, then recovery. Do not bypass the assurance gate.
- The cheap option in each phase must be a different call in each sector, in cost and not only in wording. The assurance shortcut and the patch-in-place recovery were once identical across all ten profiles — same title, disruption, confidence, residual and score — which taught players to reuse one pattern rather than read the sector. Shortcutting is now defensible where independent assurance exists outside the compromised estate (plant instrumentation, manual process supervision, clinical checks) and close to indefensible where the control being skipped is the one under investigation (settlement reconciliation, a cloud control plane, a routing management plane). `tests/content.test.ts` asserts the spread, the per-sector naming, and that the confidence and residual a player reads before choosing agree with the score.
- An evidence decision is the sector's call, not a generic one. Its wording names who the sector notifies and what it keeps running (`sectorDecisionTerms`, through `decisionLanguageFor`), acting costs the sector margin its own `containmentCost`, and watching moves it by `monitoringRecovery − 2`, so it is cheapest where the sector has its own instruments and dearest where the margin runs on time. Containing carries −1 to the next roll, stated on the option: the actor is warned and the contained systems stop showing it. Before that it was the best-looking option in every preview while the review graded it 2 of 5 at low pressure, and nothing on screen said why. Measured over 3,000 operations per difficulty both changes left win rates within noise.
- Every sector decision offers three measures: decisive, narrow and permissive. "Stop it" or "carry on" is not the shape of a real incident decision — the option that gets used is usually the narrow one, applying the control to the affected part or adding a verification step and continuing. The narrow measure earns its place by keeping the service running rather than by being a weaker copy of the decisive one: it concedes objective progress and sector protection, and costs less continuity. Tuned as a weaker copy it was chosen in 7% of bot decisions; given its own virtue it reached 22%. It must still cost something — a point of continuity, or adversary progress where the decisive measure costs no service — because when it improved every meter two laptop playtests read it as free and took it every time. `tests/content.test.ts` holds its effects between the two extremes and asserts the cost. The current Bot Commander takes the decisive measure in every sector decision (2,993 of 2,993), so the narrow measure's worth is a player's judgement the balance figures do not exercise.
- `getSectorRead` explains why service continuity and the sector's own margin can diverge — one is what the organisation is delivering now, the other is how much room is left before the sector's limit. A player watching treatment continuity fall while process safety holds is looking at a deliberate trade, and the board says so instead of leaving them to guess.
- Infrastructure monitoring and isolation consume scarce map actions. Their node posture and action history are persistent game state and must migrate safely. Their full cost — impact, continuity, sector margin and actor progress — comes from `getMapActionEffect`, which the button and the resolution both read. The sector margin was once missing from the label and could end the operation unannounced.
- Clamp impact, continuity, sector health and objective progress to their documented ranges.
- Every transition that moves a meter — procedure, evidence decision, command event, sector decision, map action, correlation and response choice — asks `breached` and settles a loss through `settle`. Map actions and correlations once left a meter at its limit with play continuing, a later correct correlation could take a lost operation back, and a response choice could win at 100 impact.
- A finished operation holds no blocking state. Every end-state check routes through `settle`, which clears `pendingDecision`, `pendingCommand` and `pendingSetPiece`; the interface must never be left asking for a choice a transition would refuse. `tests/game.test.ts` asserts this for every simulated operation.
- Name the cause when an operation is lost. `getLossReason` distinguishes the objective, impact, continuity, sector and window endings by `cause`; the investigation window is only one of five, and its detail already counts the stages, so callers add that count only for the other four. The report for the turn that ends an operation says how it ended before anything else, because that turn's own headline can be good news.
- A technique's `evidence` states the finding, not the log that held it: it must read correctly from any of its detect sources, so no `"<Source> and <source> records show"` leads. The presented narrative names the procedure and node that produced it.
- The planning bonus is the own-source bonus, `OWN_SOURCE_BONUS` (+1): a procedure that is one of the declared reading's own sources earns it whether or not the reading is right, and it is a part of `getModifierBreakdown` like any other. Correctness is rewarded where it belongs — the right source on the right route reveals the stage, and hypothesis accuracy is scored after the operation. At +2 it made the game five or six points easier for a player who never revised; at +1 that player is within two points of where they were, and sound revision is what pays.
- A sound but unlucky action — one of the declared reading's own sources, failed on the roll — does not hand the adversary tempo or objective progress. Testing what you committed to is protected; certainty is not. It is checked before the rapid-coordination grace, so a failure that was already protected never spends the grace.
- Everything waiting for the next roll — a monitored node, an inject, an evidence decision, a correct comparison — adds together under one cap, −2 to +3 (`carryModifier`), and the roll names every source. When the larger simply won, a monitored node's +2 vanished behind a comparison's +2 and the map promised a bonus the roll never showed; the map's cost line now says when the cap trims it.
- The score's investigation part allows `4 + (window − 10)` turns before it charges three a turn: six at Training, five at Operational, four at Crisis. A flat four charged a Training player for the longer window the difficulty gives them to learn in; it raised the Bot Commander's mean score by 5.8 at Training and 3.1 at Operational and left win rates unchanged.
- Two consecutive failed rolls add a persistence bonus to the next action. It is derived from the player's own turn record, it appears in `getModifierBreakdown` like any other part so the preview and the resolution stay one computation, and it clears on the first success. It is not difficulty-specific: measurement shows it moves the overall win rate by a point or two and leaves Crisis unchanged, because Crisis is lost to its other pressures rather than to the roll.
- The procedure cooldown window is `cooldownWindow`: three turns at Training and four elsewhere. Training already withholds less; leaving a beginner with no source their declared reading predicts teaches nothing. Everything that reads the window reads that function, and everything that states it in words states turns *skipped* — one less than the window, which is the number the card counts down. `tests/engine.test.ts` ties the two together.
- Each scenario offers one investigative action no other scenario has, in `sectorProcedures`. The eleven shared procedures are correct — responders use the same evidence sources everywhere — but each sector also has a reconciliation only its own people would run: manifest and berth reconciliation, historian reconciliation, approval and settlement reconstruction. It is a procedure in every sense, so everything that lists, looks up or validates one goes through `proceduresFor` and `procedureById`, and a reading's own sources come from `hypothesisSources`, never the static route list. The sector action joins that list when it tests the same route, which is how it earns the planning bonus instead of sitting outside the reasoning.
- A technique's `detect` names at least three sources, drawn from the shared procedures or its own sector's action. Each must be a source that could really see the technique: a practitioner's review removed email from a database credential, network and DNS from calls to a cloud API, and the identity platform from an added SSH key. The evidence test reads the finding's verbs as well as its nouns (records, traces, analysis … link, tie, identify), because eight findings still opened on the log in other words. A sector's stated scope names a cloud estate wherever its pool draws cloud techniques, and an OT or terminal map node does not offer the cloud source.
- Every procedure is predicted by at least one route, every technique is reachable through its own route's sources, and each route's listed sources mostly detect that route. DNS review and Email investigation were listed by nobody, so two of eleven procedures could never earn the planning bonus and only ever produced windfalls. `tests/content.test.ts` asserts all three properties. Adding a high-purity source to a route raises discrimination rather than diluting it — DNS is 78% application — so measure a candidate's purity before assuming a longer list is a weaker one.
- A critical roll draws an inject that agrees with it. A natural 20 reaches past unfavourable cards to a favourable or neutral one, a natural 1 reaches past favourable ones, and a run of failed rolls draws from the whole deck except the authorised stand-down, which is reached on a natural 20 only: drawn after three failed rolls it ended a newcomer's operation at the climax twice in two games, under a banner saying the investigation had earned it. Excluding the neutral authorised stand-down from a natural 20 dropped that ending from six per cent of operations to one, so `neutral` belongs with `good` on a 20. With none of the wanted valence left in the deck, a critical roll draws nothing rather than the next card. The deck holds twenty cards, eight good, eight bad and four neutral, appended to the table so a saved deck's indices still name the same cards. The three neutral cards other than the stand-down are trades, a gift and a cost at once (`effect: "adjust"` states its own numbers and its label says each of them, which `tests/content.test.ts` checks against the valence); a critical roll reaches past them both ways, so a 20 never hands over the cost and a 1 never the gift, and only a run of failed rolls draws one.
- The exercise card drawn on the turn that completes the chain has nothing to stand down: it eases pressure and the response goes ahead.
- A stage disclosed by the partner inject records a finding like any other, attributed to the disclosure. Without it a player can hold four confirmed stages and be unable to select one of them for correlation. When the partner discloses a stage on the same turn a procedure found one, each gets its own evidence decision, the procedure's first.
- A hypothesis premise describes a route through the whole chain, not the way in. The same four routes classify the exfiltration stage, so a premise that reads as an entry vector leaves a player no reason to pick it for an outbound channel.
- A finding is not a stage. A successful check that exposes nothing is still recorded, so every count of findings — in play and in the review — says how many confirmed a stage and how many found no stage, and each card is labelled in words. `5 findings` next to `3 stages` reads to a beginner as two of their discoveries going missing.
- The review counts command events and sector decisions separately and shows both. A single `command events` tile reading zero next to a sector decision the player just resolved looks like a defect in the game rather than two different systems.
- A scenario's `leads` are observations — what someone saw — never maxims. Quoted as "Latest from the team" beside the reading, "The safest investigative path is not automatically the fastest containment path" gave a Crisis playtest nothing to reason from at stage 4. Beyond Training the latest one is shown above the premises before the first reading as well, and a new one is drawn with each confirmed stage as well as with time: a phone playtest chose its stage-2 reading beside the stage-1 lead.
- `getKnownFacts` restates the briefing observations, the incident timeline, the stages the player has confirmed and the captain's unverified signal. It is the standing context once Operational withdraws the training aid, so it may hold nothing the player has not already been shown, and `tests/reads.test.ts` asserts it is unchanged when the hidden chain is rewritten.
- `getBeginnerReview` judges the response's cost only when a response was completed, and names what ended a lost operation rather than telling it nothing stands out.
- `getBeginnerReview` does not praise stages that were not found. A run that confirmed none is credited with the completed checks that ruled something out, or told plainly that none completed; "you confirmed 0 of 4 stages under real pressure" read as mockery after a loss.
- The Captain's prompt asks for a revision when the reading's standing says weakening or poorly supported, never merely because an empty check was once made — keyed to that, it told a player to revise for the rest of the operation while the board said the reading was holding.
- `getBeginnerReview` must not tell a player nothing stands out when the score is about to disagree. Choosing sources that find stages and naming the route correctly are separate skills; a run that did the first and not the second is told so, and only a clean record gets the all-clear.
- The modifier shown before an action and the modifier the roll resolves with are one computation, `getModifierBreakdown`, and `playTurn` adds nothing to it. No part of it may read the hidden chain, and `tests/reads.test.ts` asserts the preview is unchanged when the chain is rewritten.
- Fast resolution is the switch that skips the ceremony. With it off, every turn gets the captain's report — including the turn that found nothing, which is the turn whose result most needs explaining and which used to pass with only a strip in the column the player had just left. With it on, the report is reserved for what has to be acknowledged: a revealed stage, an inject, an adversary move or an ended operation.
- The report says what an empty result settled, and only when it settled something. A completed check that finds nothing rules out every technique its source could have seen, on any route, so the standing block appears after any completed empty check on the latest turn. A failed roll settles nothing, and captioning it as a result teaches the wrong inference.
- `getHypothesisStanding` reports how the declared reading is holding up, through `getReadingOdds`: among the techniques the scenario's published pool allows at the stage under test, which ones completed empty checks — and checks that exposed a later stage — have ruled out, and what share each route still holds. The window is per stage: it runs from the last visible change to the stage under test — a Crisis re-route that targeted it, or an adaptation after the decision on the stage before it — and a confirmation alone does not reset what a source could not see. At Crisis too, "poorly supported" was right in none of 833 cases. It names the reading that is weakening; it never names the one that is right. It replaced a count of empty checks across the reading's whole source list, under which a "holding" reading was right 29% of the time and a "weakening" one 22% — barely apart, because any one technique is visible to only about three sources. Measured over 1,500 operations, a route with nothing left open is "poorly supported" and was right in none of 1,772 cases; "holding" is right 57% of the time. A share between half and four-fifths of the starting share was still right about half the time, so "weakening" is reserved for less than half (`STANDING_WEAKENS_BELOW`).
- A route that none of the incident's published techniques at the stage under test travels by is "poorly supported" from the start, not "untested". Labelled untested, it held a player for a whole Crisis operation waiting for a check that could never come.
- Command events fire every third turn, and an operation meets one it has not met before repeating any. With three events, an index that stepped by three drew the same one every time. There are eighteen, and each option's signal words name exactly what its numbers do (`tests/content.test.ts`; four of the first three's eight signals did not), with a roll the cap leaves unchanged dropping its "Next roll" word. A campaign remembers the events, injects and sector crises of its recent operations (`recentCommands`, `recentInjects`, `recentCrises` in `parseCampaign`; `Game.recentCommands` and `Game.recentCrises`, session version 17): a new operation reaches first for an event it has not met lately, recently drawn injects go to the bottom of its deck, and a case replayed after a loss meets the sector crisis it did not meet last time. A reproducible operation ignores the memory, because a code must play the same incident anywhere. `pnpm repetition` measures it over simulated ten-case campaigns: within an act, an event repeats in 8.4 per cent of 3,000 campaigns (92 without the memory), an inject in 12.7 (77), and a sector crisis in 60 (85) — every crisis repeat is a third or later attempt at a case the Bot Commander kept losing, which two crises a sector cannot avoid.
- Correlation is prompted once two findings have confirmed stages and none has been tested (`readyToCorrelate`), at every guided difficulty, and the prompt carries a button that opens the findings and moves focus to the evidence workspace. It sits below the map, and no playtest found it unprompted. Two checks that settled nothing are not worth comparing, so they do not trigger it, and the review's correlation lesson uses the same test.
- The case theory and the infrastructure map are offered the same way, because no playtest used either unprompted. Once two stages are confirmed and no theory is recorded (`readyForTheory`), the next-step note asks for one before the comparison it improves, without naming the objective. The map is offered once, as an aside to the ordinary next step on the second to fourth turn, while actions remain and none has been used (`getMapHint`); a player who passes on it is not asked again.
- The mission brief keeps open only what shapes the first decisions — the sector's condition, the specialist and the attribution read — and folds the mode, campaign route, incident variant and director's intent behind a summary that names them. Six readouts put "Assume command" a screen and a half down on a phone.
- Every end state offers "Copy result" (`getResultSummary`): the operation, difficulty, mode, outcome, score and stage count, and the challenge code when the operation was reproducible. It names no technique, so it spoils nothing for the next player of the same code, and where the clipboard is refused it shows the text to copy by hand. **Save image** draws the same counts as a PNG on the device (`getShareCard`, `lib/share-image.ts`); the card holds nothing else, and `tests/replay.test.ts` checks it against every technique title.
- Weekly Operation (`weeklyOperation`) plays one case at Operational on one seed for the week that began on the most recent Monday (UTC); its nine-digit seed can never equal a daily one, and its case steps through the ten in order. `"weekly"` is appended to the challenge code's mode list, so every earlier code keeps its mode, and a save in it is session version 18 so that an older build parks it rather than reading an unknown mode as damage.
- Each case has a mastery ladder (`ladderRungs`, `rungsEarned`, `CampaignState.ladder`): won at Crisis, won without revising, won in half the window, won with a tired specialist, and won in Expert. Only a won operation climbs a rung: an authorised exercise clears the case but runs no response. A win in Expert has its own ending, which says what was withheld and marks the case.
- A reproducible operation's review offers to replay it with the Bot Commander. The replay carries the finished operation's variant and route, because the campaign's route may have moved and an odd variant meets the sector's other crisis; the seed carries the chain, adversary and rolls. It is a practice run and records nothing. An ordinary campaign operation drew its chain fresh, and its review says it cannot be replayed.
- Each response option states its exact effect on impact and continuity, where continuity ends up, whether that crosses into the meter's "At risk" band, and whether it would end the operation. Disruption and confidence in words did not tell a player that the decisive option in all three phases spends a third of the service.
- `getBeginnerReview` names a reading that was wrong on most turns before an untested correlation, because reading the route is the skill the game is built on.
- `getBeginnerReview` does not tell a player who revised two or more times to start revising. A playtest that revised every time the standing asked was told "when it says weakening, change the reading". It names what the record shows instead: a reading carried into a new stage after a confirmation, misses whose checks failed or used another reading's sources, or, when the reading was tested soundly, that open routes cost turns and the comparison's ruled-out marks are what is left to use.
- The four readings mark a route "ruled out" once the player's own completed checks have excluded every technique it could be using at the stage under test (`getRuledOutRoutes`); a Crisis playtest declared all four in turn to find the one still open. A route the incident simply does not use at that stage is not marked: marked before any work was done it handed over most of the answer, and where it left one route, all of it. It names only routes that are out, never the one that is right, and `tests/simulation.test.ts` asserts across bot operations that the route the hidden stage uses is never marked.
- Every stage offers four techniques across at least three routes, and a borrowed technique is one its new sector can see through shared sources or its own action, never another sector's. At three techniques, most stages had two routes in play and six had one, so the reading was mostly decided before a check. `tests/content.test.ts` asserts both. Widening the search cost the Bot Commander about six points, which one more turn at each difficulty gave back.
- A finding that confirmed a stage names its stage and route on its evidence card. A causal judgement turns on consecutive stages or a shared route, and without them a player could judge only on timing — the very mistake the result text corrects. The case-theory picker states the current objective assessment, in its own button's words, once two confirmed stages allow one.
- The Bot Commander revises on that standing. It starts from the route of its latest find and moves to the most open route when its reading is poorly supported or weakening, keeping a revision until the record turns against it. It used to snap back to the latest find's route every turn, and lost most operations to the window with three stages confirmed.
- A win earns back leadership trust at `(score - 48) / 7`, at least one point, and a loss still costs eight. It was `(score - 45) / 7` until the investigation allowance grew with the window and raised Training and Operational scores; left there, collective resilience rose from 29 to 40 per cent of 600 simulated campaigns, and 48 puts it back at 33. At `(score - 50) / 8` 120 simulated twenty-operation campaigns by a command that won two in three ended 27 per cent on "fractured trust" and played a fifth of their operations a map action short; now the endings are 53 per cent guarded stability, 33 collective resilience and 12 fractured trust. At `(score - 40) / 6` the best ending became the usual one.
- Expert withholds the standing, the ruled-out marks, the per-card reads and every prompt, and the review's advice in Expert never points at one of them: it asks for the same habit kept by hand.
- The team rests between operations: benched specialists recover two points of fatigue and the one just deployed recovers one. A twelve-operation campaign simulation found the deployed specialist never recovered at all, so a player who kept the default started every operation after the first at five of six (`SPECIALIST_EXHAUSTED_AT`), where the bonus no longer applies. The deployment screen says so when the chosen specialist is that tired. Practice runs under the Bot Commander record nothing, as the setup and the in-game banner both say, so campaign progression is measured by simulating a human player's results through `recordCampaignResult`.
- The campaign explains itself. The assignment offered on arrival and after a review is the first case not yet cleared (`nextCase`), so a reload never offers a cleared case and a lost one comes back. The review lists what the operation changed and why (`campaignChanges`: trust, readiness, unresolved access, the case) and why the campaign is on its route (`routeReason`); locked milestones state the experience they unlock at, the review names experience gained and any milestone it unlocked, and the career card states what trust and readiness do at their thresholds (`standingEffects`, the numbers `newGame` applies). A specialist's bond is shown as rapport with that specialist, not "team cohesion", which fell after a win when the player changed specialist. The mode picker says that every mode's result counts toward the campaign but only Campaign operations are shaped by its standing, and a non-campaign brief names no route. Daily Operation plays today's case, chosen from the date, so every commander does meet the same case. A returning-player playtest graded the campaign C+ on all of these.
- Campaign standing must change what an operation has to work with, not only its opening numbers: established sources, command actions, the investigation window and the rapid-coordination grace. Seniority follows results — `recordCampaignResult` scales the reward by outcome, so a command that keeps losing does not reach the tier of one that keeps winning.
- The training aid is `getTrainingPrompt`, and it prompts the next step in the reasoning — declare, test, revise, correlate — never the source to click. It must never return `nextEvidenceSource`: an aid that names the source walks the player to every stage while the rest of the interface tells them the same action tests nothing, and it scored three out of ten on hypothesis accuracy. The sources it lists are always the declared reading's own, so it cannot contradict `getDiscriminatingRead`.
- Training discloses exactly one thing the player could not derive: the `clue` on the next unconfirmed stage. It names what was observed, never the technique or the source that would expose it, and it is available at Training difficulty only. Without it the opening hypothesis is a coin flip between four routes and the game teaches nothing.
- Absence is evidence only when the check completed. A failed roll settles nothing about a source, so `getHypothesisStanding` and `getDiscriminatingRead` count it as inconclusive and never against the reading.
- Anything shown before an action, including `getDiscriminatingRead` and `getHypothesisStanding`, may use only state the player has already declared or observed, with the Training clue as the single stated exception. It must return the same value when the hidden chain is rewritten underneath it, and `tests/game.test.ts` asserts this.
- Hypothesis accuracy credits sound reasoning, not only correct answers. A turn scores in full when the declared reading matched the stage under test, and half when the reading was wrong but properly tested — one of its own sources spent, or a source marked "Can also test this reading" (`sourceSeesReading` on the record before the turn), and the check completed — which rules it out. The board ruled a route out on such a check while the ledger paid it nothing, and a phone playtest read that as two rules. That half is paid once per reading for each technique under test — the record of what has been paid is keyed to the turn's `hypothesisTarget`, because clearing it on any turn that revealed something paid a reading twice when a partner disclosure or a later-stage find landed while the stage under test was still open — and only while the record before that turn still left the reading's route open (`getReadingOdds`), so revising is rewarded and re-declaring a reading that has come back empty, or that other checks have already excluded, is not; a failed roll settles nothing and earns nothing. Scoring exact matches alone put sound play and random play both near three out of ten while perfect knowledge scored ten, which is why players kept reading the number as arbitrary. Measured over 800 Operational operations the spread is 10.0 for a player who knows the answer, 6.1 for the revising Bot Commander, 3.7 for one that never revises and 3.8 for a reading chosen at random each turn and tested properly. With two routes in play at most stages it was 7.5 / 4.4 / 3.3; with three or four, reading the route is harder for everyone, and sound play still scores well clear of both. Before the open-route condition a random reader scored 4.8; measure a random player with a policy that really is random — wrapping the revising bot let it set its own reading back before every procedure, and the "random" figure came out at the sound one.
- Each turn records what its hypothesis was tested against. `getScoreBreakdown` and `getHypothesisLedger` both read those fields, so the score and the ledger that explains it cannot disagree. They are graded after the operation; nothing during play reads them.
- A source shared between routes can expose a stage further along than the one under test. That is a find, not a correct prediction: the turn is marked `windfall`, and the ledger must name the route the stage under test actually used, so a score of nothing is checkable against what the player saw.
- Evidence correlation is valid on consecutive stages or a shared route, and the result text must say which. Naming the two systems taught that sharing a node is the reason, which it is not.
- Challenge codes must reproduce the same scenario configuration and random sequence, so they carry `CHALLENGE_VERSION` (`BC6-…` now), and any change to a scenario's technique pools, the techniques or the seeded draws increments it. Widening the pools once made every shared code decode cleanly into a different incident; an older code is now refused and named as outdated (`isOutdatedChallenge`) rather than reported as mistyped. A reproducible operation carries `Game.seed`, and `playTurn` derives its d20 from the seed and the turn index. Leave `seed` null for ordinary campaign play, and draw its hidden chain fresh as well: a chain taken from the date replayed the same answer on every restart that day. Daily Operation plays today's seed unless a loaded code says otherwise, and a loaded or generated code covers the next operation begun and is then spent. The date is read on the client after hydration, never in a state initialiser of the prerendered page.
- Any new persistent `Game` field requires a `SESSION_VERSION` increment and a safe migration in `lib/session.ts`.
- Any new campaign field requires a backward-compatible default in `parseCampaign`.
- Campaign routes and incident variants must remain deterministic for the same challenge seed and campaign state.
- Case-theory changes are blocked by every pending decision state and must never reveal the hidden objective.
- Adversary identity remains progressively attributed. Do not expose the profile name in opening briefings or low-confidence operational text.
- The assessed objective stays unconfirmed until two stages are confirmed, however many turns pass, and nothing may name it before then — including an accessible name. The objective bar's label once read the hidden objective to screen readers from the first turn.
- Undo exists only for map actions, whose effects are stated before they are chosen. A procedure's result is information: undoing it after seeing a stage, an empty source or a failed roll hands over the answer or a free re-roll.
- Evidence correlation records both the player's causal assessment and whether that assessment was correct. Timing alone must not be presented as causation.
- A technique borrowed into another sector must fit that sector's stated scope, not only the content rules. The energy and maritime incidents briefly drew cloud role escalation and cloud storage export although neither briefing has a cloud estate, and the water plant drew an application consent grant; they now draw a jump-host pivot, an authorised key addition, a TXT channel, password spraying and a hidden privileged account.
- Every scenario keeps at least three techniques no other scenario can draw, and `tests/content.test.ts` asserts it. A chain assembled entirely from the shared pool is the sector's vocabulary painted onto a generic incident: the test to apply is whether the chain could move to another sector without changing a single technical noun. Banking, government and telecommunications each had one such technique and now have three to five, which is why a settlement incident can run approver takeover, entitlement widening, payment-support tampering and reconciliation suppression rather than a cloud pipeline compromise under a banking headline.
- The technique pool grows as sectors earn their own techniques. Assert that every stage draws from a pool of the same size, never a fixed count, or each authored addition becomes a test edit.
- The node in a finding's narrative is where collection was focused, not where the technique lives. The finding leads in its own words and the attribution follows, because `Identity audit at the payment gateway` in front of a mailbox relay asserts a location the game never established.
- New scenarios must include a topology, sector system, two set pieces (`sectorSetPieces` and `secondSetPieces`; the odd incident variants meet the second), seven incident variants of which the first three never move, an adversary profile mapping and complete four-stage choice sets.
- Each adversary profile has a signature mechanic in `playTurn` that punishes a habit the game teaches against, and a counterplay the review names after the operation. The three added with the second content batch punish an unused map by the third turn (Grey Lantern), two confirmed findings left uncompared (Hollow Choir) and service continuity below 60 (Ember Shift). `pnpm balance` prints each profile's win rate by difficulty; read it against the difficulty's overall rate, since each profile is drawn by different scenarios.

## Experience requirements

- The game must remain fully usable with mouse, keyboard and touch.
- Maintain visible focus states, semantic controls, accessible names and live announcements for material state changes.
- Support widths from 320 px mobile screens through desktop without horizontal page overflow, clipped text or unreachable controls.
- Keep essential tap targets at least 40 px high, preferably 44 px on mobile.
- No label may break inside a word. The meters give the label the meter's full width and set the number beside its bar, at every width: on a phone a scenario's own continuity label ("connectivity continuity", "trusted maintenance access") had about 55 px beside the number and broke mid-word, and on a laptop "business service integrity" ran to three lines while the other two took one, leaving the three numbers at three heights.
- Never rely on colour alone to communicate state.
- A hover state must not move an element out from under the pointer. A lift of even a pixel un-hovers it at its edge, it drops back, and it lifts again every frame; that flicker kept the first response option permanently unstable at 834 px once the response moved to the top of Command. Lift only what keeps the vacated strip as part of the element, as procedure cards do with `::after`.
- No overlay may place initial focus on a control that changes state. The action sheet's first tabbable control is a plan toggle, so it moves focus to the sheet itself on open; otherwise Space — the key that scrolls a dialog — commits a plan change, and Rapid sits two tabs from where focus lands. The Captain's Report with a decision pending and the settings dialog do the same.
- When a blocking panel, a new response phase or an end state replaces the control just used, focus moves to its heading through `useRecoverFocus`, and only when focus was actually lost.
- High contrast is carried on the document root as well as the shell, because dialogs and sheets render outside the shell.
- The single-key shortcuts can be turned off in settings (WCAG 2.1.4) and never fire from an input, select or editable field.
- Scope and intensity persist between turns. The selection says so in words as well as colour, carries `aria-pressed`, and the carried plan is stated before the options and on the procedure heading outside the sheet — a plan that silently stays selected accumulates impact and fatigue a beginner never chose.
- A meter change is shown with its direction, through `describeChange`. Impact rising is bad and continuity rising is good; a bare signed number leaves a new player guessing which. Anything shown during an operation names the meter as its readout does, through `describeMeterChange`: the scenario's own continuity and sector titles and "Adversary progress", never "Continuity", "Sector confidence" or "Actor progress", which named nothing on a Maritime screen.
- Field vocabulary carries a plain-language translation in `plainLanguage`, and the review opens with four plain sentences from `getBeginnerReview` before any scoring.
- The four premises and the Training clues are written for a player with no security background, because they are the first thing a newcomer has to reason from. "Trust relationship", "control plane" and "automation identity outside its workload boundary" sent a first playtest to the wrong reading on its first turn; a clue that belongs to the cloud route says cloud, not only "identity" or "credential". Words the interface still uses — endpoint, C2, pivot, egress, DNS, established source, inject — are in the glossary. The report states the die ("Rolled 16 on the d20") and the field guide's quick start the target at each difficulty; a procedure card labels an established source "Established source +2", set like the own-source tag, and leaves an ordinary one unlabelled, and a finding that settled nothing is titled "came back empty", not "exception".
- A clue says what someone on the team noticed, in words they would use: programs and computers rather than processes and hosts, sign-ins rather than authentication, and no named mechanism (service tickets, timer units, high-entropy parameters, resolver telemetry). It may leave two routes plausible through what happened, never through a word that belongs to the other route, and a cloud-route clue names the cloud. The premises use the same everyday words, so a newcomer can match one to the other.
- Glossary terms are explained where they are read. `glossaryParts` marks each term's first use in a passage, longest term first, plural or hyphenated, and `Glossed` renders it as a quiet underlined control that opens the meaning in brackets after the word. It is used in prose only — the clue, the report's narrative, the action sheet, the briefing and the declared reading — never inside another control, so it does not reach the premise cards or option buttons. A term that appears in play belongs in `plainLanguage`.
- The Training clue stays on screen for the whole stage it describes, whatever else the next-step note is asking for. It once dropped out on the turn a reading first held and whenever a comparison or a case theory was asked for, and a playtest spent four turns on sources that could not see the stage while it was gone.
- A plan's effects and a turn's movement are told apart. The action sheet says the plan's effects add to what every turn costs; the report lists the plan, then "This turn:" with all four changes in the readouts' names and the reason (a find, an empty check or a failed one), then, once a response is chosen, what that response did. The response sequence opens each later phase on what the previous choice did, in place of repeating the sector constraint.
- The ledger and the score read one per-turn credit (`turnCredits`): full, half or none, with the reason a miss earned nothing. A row read "NO CREDIT · +1" for a turn the score paid half, and the roll bonus beside the badge read as part of it.
- `getBeginnerReview` gives only advice the record supports: empty checks of the reading's own sources are told to revise rather than to "prefer a source your reading predicts"; a comparison is asked for only when two confirmed stages stood before the last turn; and calls graded two or less are named with their reason before "nothing stands out".
- The reading's bar names the stage it is being tested against ("Reading for stage 2, Pivot & escalate"), and a confirmed stage in the report names its route, because a premise describes a route at any stage and a playtest read it as the whole incident's.
- An own source that cannot see any technique the declared reading could be using at the stage under test, from the scenario's published pool (`sourceSeesReading`), says so on its card ("CAN'T SEE THIS STAGE") and in the action sheet, and the Training aid does not suggest it. A playtest spent two such checks while the board read "holding" and found out why only in the review. It reads the pool, never the chain, and `tests/reads.test.ts` asserts it is unchanged when the chain is rewritten. The ledger no longer says such a check "ruled the reading out"; half credit is for testing a reading properly.
- The sector's own margin is always in view under the case title ("Sector margin 62 Clearing-window integrity"), and a loss to it is titled in its name ("Clearing-window integrity reached zero"). A Crisis playtest lost to a meter it had never seen, under a loss title that was a third name for it. The review names a loss to any meter after the two notes on the reading and before advice about empty checks or an untested comparison, and for the sector quotes the sector's own rule.
- A carried reading is questioned at a new stage: once a stage has been confirmed since the reading was chosen, the Training aid asks "New stage: does … still fit?" instead of "Test …", which read as its recommendation. It asks until the reading has been used at the new stage, whatever the standing reads, and ahead of a case theory or a comparison: keyed to an "untested" standing and behind the theory prompt, a phone playtest carried a "Holding" reading into stage 3 and was never asked.
- The roll's carried bonus names what set it (`Game.nextModifierSource`, session version 15): "Monitored Access boundary +2", "Inject: …", "Evidence decision: …", "Command event: …", or "Correct comparison of findings". Two or more are each named with their own share and how they combine ("Inject: Hard going −2; Monitored Access boundary +2, together"), and a named part stays in the breakdown at zero: when a penalty cancelled a monitored node's +2 the label was dropped and the map action looked wasted. Each turn records the parts its roll was made of (`Turn.parts`, session version 16), and the Captain's Report names them as the action sheet did, instead of "own source +1, other parts +5". Every preview of a change to the next roll reads `describeRollShift`, which says when the cap trims it. One label, "Since your last roll", covered all of them and three playtests could not tell what an action had earned.
- A preview states only the change a meter can take: a sector decision promised "margin +5 better" at 100. A command event's signal words name what the numbers do, never a benefit with no number behind it ("Higher confidence" sat beside a cost and nothing else). The comparison states a right and a wrong call's exact effects, and each later response phase opens on what the previous choice did to the two meters. The selected node on the map names the sources map focus helps. A source outside the reading's list that can still test it carries "Can also test this reading" on its card, read from the published pool like the blind tag; with every own source cooling or blind it is where the turn goes. After a sector decision Investigate names it until the next procedure. The comparison's larger reward is stated as what it is, a right causal call made with a case theory that names the objective. The Captain's prompt says a reading's sources are all cooling or blind before it gives the critical-pressure advice, which otherwise told a player to run a source no card could offer. The turn that ends an operation is headed by how it ended. A capped carried bonus says what its parts came to before the cap.
- Every choice states its exact effect before it is made. Command events show it under their signal words, as sector decisions, map actions and response options do. Each evidence decision option reads its own line from `resolveDecision` itself, so the preview and the outcome are one computation; five options in words, then a number in the report, read to every playtest as a hidden cost. The quality grade stays for the review. At Training the decision also states the pressure the review grades by (business impact 55 or more, or the actor's pace at Accelerating or Pressing hard) and which kind of response that favours. The top pace reads "Pressing hard", not "Executing objective", which sat beside an adversary progress of 19. A response option's effect is the change the meter will actually take, so nothing below zero is promised.
- A find further along the chain says so in the report ("This is stage 3 … the stage you were testing is still open") and shows the standing, because a beginner read a cloud find while testing stage 1 as proof of the cloud reading. Findings that confirmed nothing are labelled "found no stage", since a completed empty check does rule something out.
- The review's counterfactual about revising counts only changes made with no completed check since the last one; counting every change told a player who revised on the standing that revising was the mistake.
- A route with no technique at the stage under test is labelled "Cannot explain this stage", and the prompts say so in those terms rather than "the record no longer favours this reading", which a playtest read as the game judging a check it had not yet made; the ledger names that case apart from a route the player's own checks excluded. An own source that cannot see the reading carries one tag ("Own source +1, can't test this reading here"; "blind at this stage" read as the source finding nothing at all, and then it found a later stage), not two that read as a contradiction, and when every own source is cooling or blind the Captain's prompt says so.
- A find further along the chain is headed "A later stage was found."; a find on a route other than the declared reading says the route was not predicted. The report's escalation is headed "Situation escalates", because several read as defender actions under "ACTOR MOVEMENT".
- A sticky strip inside a scrolling panel sits in that panel's padding: its sticky edge is inset by the padding, so a strip at `top:0` rests over the content's first line; the report's cue uses a negative bottom for that reason.
- The decision's pressure line shows at every difficulty but Expert, because the review grades every decision against it; an Operational and a Crisis playtest were each graded on a rule they were never shown. ## Change discipline

- Use `apply_patch` for hand-authored changes.
- Preserve unrelated user changes in a dirty worktree.
- Avoid broad refactors during a feature or bug fix unless they are required for correctness.
- Do not edit generated build output or vendored files in `components/ui` for ordinary styling changes.
- Do not add dependencies when the existing stack can implement the requirement.
- Update `README.md` whenever commands, architecture, game modes, persistence or major systems change.

## Required verification

Run these checks before committing code changes. `.github/workflows/verify.yml` runs the same checks and every browser suite, against a production build, on each push to `main` and each pull request. Vercel deploys `main`, so a red run there is a broken production build: fix it before anything else.

```bash
pnpm test
pnpm lint
pnpm exec tsc --noEmit
pnpm build
git diff --check
```

`tests/e2e/responsive-game.spec.ts` builds the response phase from the engine and resumes it from a saved session. Do not make a browser fixture depend on a bot run winning under a stubbed random source: that run is decided by one constant, and a balance change silently takes the whole suite with it.

Run `pnpm test:a11y` for any change to markup, labels or the responsive rules that hide them; it must report zero violations, and `pnpm test:persistence` for any change to stored state. `pnpm test:e2e` runs every browser suite in Chromium, including the visual baselines and the performance budgets; `pnpm test:browsers` adds WebKit and Firefox where they are installed, as CI does; run it for any change to focus handling or keyboard behaviour, which `tests/e2e/keyboard.spec.ts` covers. A browser test that acts on the page waits for it to hydrate (`networkidle`) first: the page is prerendered, so it is visible before its handlers exist, and the dev server makes the gap wide enough to fail on. For engine changes, add a deterministic assertion and ensure all simulated playthroughs terminate. For UI changes, exercise the affected flow in the managed preview and check 320, 375, 430, 768, 810, 820, 834, 1024, 1080, 1194 and 1280 px widths. Treat 768–834 px portrait and 1024–1194 px landscape as explicit iPad targets. A successful build does not replace interaction and responsive checks.
